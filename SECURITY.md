# SECURITY.md — Reporting a vulnerability in the repo itself

This file is about the **repository and site** (the code and data in this repo),
**not** about the offensive/defensive tools it maps. For responsible use of the
*mapped tools*, please follow [ETHICS.md](ETHICS.md) and [SCOPE.md](SCOPE.md).

## Reporting

Please **do not** open a public issue for vulnerabilities in the repo. Instead,
email `5h4d0wn1k@users.noreply.github.com` with:

- a short description of the issue (XSS in the renderer, data injection, broken
  linking, exposed secrets, etc.),
- affected file/URL and steps to reproduce,
- a suggested fix (optional but appreciated).

You will receive an acknowledgement within 72 hours and an update as the issue
is triaged. We follow **responsible disclosure**: a fix is published before or
together with the public announcement.

## Disclosure timeline

| Step | Target |
|------|--------|
| Acknowledgement | within 72 hours of the report |
| Triage (reproduction + severity) | report status updated within 5 business days |
| Fix + coordinated release | before or together with a public advisory |

If you reported a reproducible issue and it reaches 90 days unremediated, you are
free to disclose publicly after that point with acknowledgement of this project.

## Scope

In scope: `docs/index.html`, `scripts/build.py`, `docs/data/*`, workflows, docs.

Out of scope: the third-party tools linked by the map, and any use of them
against systems you do not own.

## Suggested hardening

- Data files (`tree/*.json`) are treated as trusted build input; the site
  escapes rendered strings. Any change that routes raw JSON into the DOM
  without escaping should be treated as a security bug.
- `docs/data/tree.json` is regenerated by CI (`scripts/build.py`) — commits to
  it should come only from that pipeline or from local runs of the same script.
